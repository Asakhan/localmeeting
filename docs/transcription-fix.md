### 교정 병목과 변경

- 이전 경로는 5,000자씩 나눠 Qwen 9B에 단어/문법 교정을 각각 요청했다. 이 전사는 약 8번의 순차 생성 요청이 필요하다. 저장된 로그의 생성 속도는 약 11 tokens/s, 요청별 출력 상한은 3,000 tokens였다. `summary_error.log`에는 문법 교정 응답 길이 초과가 기록돼 있다. 전체 50분의 시작/종료 로그는 없어 사용자 보고 시간을 독립적으로 확정하지는 않았다.
- 현행은 Kiwi CONG 오타·형태소 분석과 `theSOL1/kogrammar-base`의 CTranslate2 INT8/FP16 배치 교정이다. Qwen은 회의록 요약에만 쓴다. GPU 모델은 STT → KoGrammar → Qwen 순차 로딩/해제한다.
- KoGrammar가 제안한 숫자 단위 변경(명→개), 문장 완성, 존댓말 추가, 보조동사 누락 등을 실제 데이터에서 발견하여 자모·형태소·부정·숫자/단위·등록 용어 검증으로 차단했다. 원문/수정 이력은 계속 보존한다.
- RTX 5070 Ti Laptop에서 모델을 처음 로딩한 60분 상당 입력(553행/21,734자)은 **18.55초**, 이어 처리한 실제 입력은 **5.06초**. 60분 상당 입력은 실제 55분35초 전사에 앞부분 4분25초를 추가한 것으로 별도 60분 실녹음은 아니다. 각 입력 전체를 검토했으며 시간 예산으로 생략한 청크는 없다. 근거: `test-output/fast-benchmark/metrics.json`.
- 이 측정은 단어·문맥 교정만이다. 음성 전사, 화자 재분석, 회의록 요약 시간은 포함하지 않는다. CPU·다른 부하 환경에서 60초 보장을 의미하지 않는다. 추론 배치 사이 50초 예산을 검사하며 미검토가 남으면 이력에 명시하고 오디오를 보존한다.

## 적용

- 한국어/혼합 언어 모두 large-v3 INT8을 사용한다.
- 발화 구간과 단어별 시간·신뢰도를 검사한다. 무음, 0초 길이, 지나치게 빠른 정렬, 정렬 없는 문장을 제외한다. 낮은 단어 신뢰도는 `[청취 불명확]`으로 표시한다.

## 문맥 기반 후처리

추가 보고된 `화자는 반드시 생명으로만 나와야 되겠죠`와 `후속위팅은 없습니다.`에 대응해, 음성 모델 종료 후 기존 로컬 Qwen 모델로 교정 후보를 생성한다. 회의록 요약 전에 교정을 완료하며 두 모델을 동시에 GPU에 올리지 않는다.

후보는 원문에 유일하게 존재하는 부분 문자열이어야 한다. 한글을 자모로 분해한 편집 거리가 3 이하이면서 자모 길이 대비 50% 이하인 후보만 적용한다. 이는 발음 유사성의 근사치이며 실제 음성 대조는 아니다. 숫자 및 비한글 변경, 부정 표현 변경, 등록 용어와 명시적인 이름 설명 문장의 변경은 거부한다. 단어 블랙리스트나 일괄 치환은 사용하지 않는다.

교정 결과는 `transcript.jsonl`에 저장하되 변경 행에는 `raw_text`를 남긴다. `transcript_corrections.json`에는 행 번호, 변경 전후, 모델의 제안 근거를 기록한다. 다시 처리할 때는 원문을 기준으로 교정하여 수정이 누적되지 않는다. 교정 실패 시 원 전사를 유지하며 정상 완료/음성 삭제로 진행하지 않는다.

검증: 단위 테스트 32개 통과. `verify_correction.py`의 실제 로컬 모델 검사에서 두 오류를 각각 `한명`, `후속미팅`으로 교정했으며, 정상적인 `생명은 소중합니다`, 숫자/부정문, 제품명 설명은 유지했다. 이 검사는 텍스트 후처리 검증이며 음성 인식 자체의 정확도 검증은 아니다.

### 고유명사 및 문법 교정 확장

`아사검`, `아사검의 회의록`을 기본 용어로 등록했다. 기존 사용자 설정과 병합하고, 저장된 과거 회의의 재처리에서도 음성 인식 힌트와 교정 입력에 적용한다.

짧은 단어 치환에 한정했던 검사를 확장해, 긴 구절에서도 발음이 가까운 국소 변경(최대 6음절)을 허용한다. 등록 용어가 포함되었다는 이유로 구절 전체를 거부하던 방식은 등록 용어 자체가 훼손되는지 확인하는 방식으로 바꿨다. 숫자·비한글·부정 표현 보존 검사는 유지한다.

단어 교정 후 별도 문법 검수 요청으로 조사·어미 오류를 확인한다. 같은 로컬 모델을 순차적으로 사용한다. 교정 내역의 `stage`로 단어/문법 단계를 구분하며 두 단계 모두 최초 `raw_text`를 보존한다.

추가 검증은 사용자 보고 문장, 이름 보존, 일반적인 조사 오류 및 정상 문장 보존을 포함한다. 텍스트 기반 추정 교정이므로 모든 발언을 정확히 복원하는 것은 보장하지 않는다.

단위 테스트 38개와 실제 로컬 모델 검증을 통과했다. `아사범의 회의록` → `아사검의 회의록`, `아사검의 회의로운 프로그램이 성능이 좋다` → `아사검의 회의록은 프로그램의 성능이 좋다`, `오늘 회의은` → `오늘 회의는`을 확인했다. 정상적인 말투를 문어체로 통일하려는 제안은 제외한다.
